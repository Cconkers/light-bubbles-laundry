## Objective

Resolver la fricción del **primerizo** y de quien llega con prisa: dudas típicas antes de
visitar el local (reserva, pago, productos, tamaño de colada, horario, ubicación), con una
sección FAQ en la home y ancla real `#preguntas`.

Hoy el Header “Preguntas” apunta a `#cta` (cierre genérico). Esta SPEC sustituye ese
destino por una sección dedicada, usable **sin JavaScript**, alineada a la claridad de
producto y a D-010.

### Alcance

Incluye:

- Nueva sección en la homepage, **después de Cómo funciona y antes del CTA final**
- Ancla canónica `id="preguntas"`
- Exactamente **seis** ítems FAQ en [`src/data/content.ts`](../../src/data/content.ts)
- UI accordion con **`<details>` / `<summary>`** nativos (cero JS obligatorio, D-004)
- Header “Preguntas” → `#preguntas` (dejar de usar `#cta` para ese ítem)
- Tipografía `.type-*` / tokens; superficie light-first (D-005)
- Enlaces internos a `#tarifas` / `#contacto` / `#como-funciona` donde ayuden
- Nota aditiva en [`001-home.md`](./001-home.md) al implementar (Rule 12)

Excluye:

- Página aparte `/faq` o `/preguntas`
- Sobre nosotros
- Audio ambiental ([`SPEC-002`](./002-audio.md))
- Formularios o chat (D-011)
- `schema.org` FAQPage (fuera de alcance; SPEC SEO futura)
- Librerías de accordion / headless UI
- Afirmar métodos de pago, precios o “detergente incluido” como hecho no confirmado

## User

| Perfil | Qué necesita | Implicación de diseño |
|--------|--------------|-----------------------|
| **Primerizo / estancia temporal** | Saber si hay que reservar y cómo se usa | Primera pregunta visible; respuestas cortas |
| **Con prisa** | Horario y ubicación en un toque desde el nav | Ancla `#preguntas`; ítems de horario/ubicación con datos reales |
| **Sensible al precio / gran volumen** | Si cabe edredón / dónde ver tarifas | Remitir a `#tarifas` sin inventar kg en la FAQ |
| **Teclado / lector de pantalla** | Expandir cada pregunta sin trampa | `<details>` nativo; `summary` con texto completo de la pregunta |

## Datos: confirmados vs candidatos vs placeholders

### Confirmado (usar en respuestas)

| Dato | Valor | Ítem FAQ |
|------|--------|----------|
| Horario | Lunes a domingo, de 7:00 h a 23:00 h | ¿Cuál es el horario? |
| Dirección | C. Virgen de la Cinta, 41011 Sevilla | ¿Dónde estáis? |
| Teléfono / email | Ver `contact` en `content.ts` | Opcional en respuesta de ubicación/contacto |
| Modelo | Autoservicio, acceso libre | ¿Necesito reserva? → no hace falta reserva |

### Copy candidato (ajustable sin SPEC nueva)

| Elemento | Texto candidato |
|----------|-----------------|
| `h2` | Preguntas frecuentes |
| Apoyo | Resolvemos las dudas más habituales antes de tu visita. |
| CTA bajo FAQ (opcional) | ¿Sigues con dudas? Contáctanos → `#contacto` |

### Placeholder / prudencia (D-010)

| Tema | Regla |
|------|--------|
| Métodos de pago | No afirmar “solo tarjeta” / “solo monedas” como hecho. Copy prudente o `[PLACEHOLDER: métodos de pago aceptados]` visible en la respuesta, o remitir a “consulta en el local / Contáctanos”. |
| Detergente “incluido en el precio” | No afirmar inclusión. Sí se puede decir que hay productos en el local (alineado al copy de Servicios). |
| Capacidades / precios | Remitir a `#tarifas`; no repetir importes como definitivos. |

## Information Architecture

Orden de la home tras esta SPEC:

Hero → Benefits → Servicios → Tarifas → Cómo funciona → **FAQ / Preguntas** → CTA final → Ubicación → Footer

### 1. Sección FAQ

- `id="preguntas"`
- Landmark: `<section aria-labelledby="faq-heading">`
- `h2` — “Preguntas frecuentes”
- Apoyo corto — una frase
- Lista de **6** `<details>` (uno por pregunta), en este orden:

| # | Pregunta | Respuesta (intención) |
|---|----------|------------------------|
| 1 | ¿Necesito reserva? | No. Es autoservicio: ven en horario de apertura y usa una máquina libre. |
| 2 | ¿Qué métodos de pago aceptáis? | Prudente / placeholder D-010; no inventar. Remitir a contacto o local. |
| 3 | ¿Hay detergente en el local? | Sí hay productos disponibles en el local (candidato). **No** decir “incluido en el precio”. |
| 4 | ¿Puedo lavar edredones o cargas grandes? | Sí hay máquinas de distintas capacidades; ver `#tarifas` para tamaños. |
| 5 | ¿Cuál es el horario? | Texto de `contact.hours` (confirmado). |
| 6 | ¿Dónde estáis? | Texto de `contact.address` + enlace a `#contacto` (mapa). |

- Cada `<summary>` muestra la pregunta completa (objetivo táctil ≥ 44px de alto en la zona clicable)
- El cuerpo de la respuesta usa `.type-body` / `.type-small` y `--color-text-secondary`
- Superficie clara (`bg-background-alt` o `bg-background`); ítems con borde `--color-border`, radio `--radius-card` o `--radius-md`
- Sin `card-featured` en este grupo
- Opcional: franja o enlace “¿Sigues con dudas? Contáctanos” → `#contacto` (Button o enlace de texto; un solo control)

### 2. Cableado de anclas

| Origen | Destino |
|--------|---------|
| Header “Preguntas” | `#preguntas` (**cambia** desde `#cta`) |
| Móvil: mismo ítem | `#preguntas` |
| `#cta` | Sigue existiendo para el CTA final; ya no es destino de “Preguntas” |

### 3. Datos en `content.ts`

Estructura orientativa:

```ts
export const faqIntro = { title: '...', subtitle: '...' };

export const faqItems = [
  { id: 'reserva', question: '...', answer: '...' }, // answer puede ser string o bloques
  // ...
] as const;
```

Las respuestas que citan horario/dirección **leen** `contact` (una sola fuente de verdad), no duplican literales sueltos que puedan divergir.

## Responsive requirements

### Mobile (< 768px)

- 1 columna; full width dentro de `--gutter`
- `summary` con padding generoso; sin scroll horizontal a 320px
- Una pregunta abierta no debe empujar contenido fuera de viewport de forma rota

### Tablet (768–1023px)

- Misma columna; ancho máximo de lectura ~65ch centrado o limitado con `--prose-max` / max-width en el listado

### Desktop (≥ 1024px)

- Listado centrado en `--content-max`; ancho de lectura cómodo (no estirar líneas a 72rem enteros)
- Sin grid 2 columnas de FAQs (una columna = escaneo más claro)

---

## Accessibility

- Un solo `h1` (Hero); esta sección: `h2`; las preguntas van en `<summary>` (no hace falta `h3` por ítem si el summary es el nombre accesible; si se usa `h3` dentro de summary, mantener jerarquía sin saltos)
- `<details>` / `<summary>` nativos: operable por teclado (Enter/Espacio en summary)
- Foco visible en `summary` (`focus-visible:shadow-focus`)
- Contraste AA en pregunta y respuesta (D-007)
- Enlaces dentro de respuestas con nombre claro (“Ver tarifas”, “Ver ubicación”)
- `prefers-reduced-motion`: sin animaciones propias; si se anima el chevron, respetar reduced-motion
- Zoom 200% sin pérdida del summary ni del enlace de contacto
